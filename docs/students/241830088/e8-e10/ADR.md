# ADR：保留受限缓存机制，以独立预期与动态证据核对

日期：2026-11-03；作者身份：241830088；状态：本次实验采用。

## 背景与约束

课程参考 scan 以 GCC -MM 观察显式 C/Make 目标，原 BuildChecker 可产生真实 strace 与 Make 数据库。要求完成 E8 历史复用、E9 逐提交更新和 E10 六类各五次配对。服务器无法稳定直连 GitHub，但本机 API 和 SSH 可用。原 E7 受保护分支检查必须保留。

## 决策

保留教学 lab.py 的缓存 key 和算法，不把实验扩展写成完整 EChecker 实现。预处理行、源文件集合、TAB 配方、受支持 CFLAGS 或编译器版本首行变化时保守刷新两个目标；key 相同复用实际图，但始终重新解析声明并计算 MD/RD。选择明确边集的独立测试与不调用 scan 的产物审计，另在 E8、E10 末态和新增两跳包含场景执行真实 BuildChecker 对象投影核对。

六场景按序累积，各场景五次都使用同一历史，保存每一对 JSON，并同时报告增量/全量中位数、双方范围及比值。实际增量更慢的场景照实保留。

通过本机 API 发布与本地相同 SHA 的 Git 对象，使用包含 main 与个人分支的 Git bundle 传入服务器；逐次校验源 SHA、镜像 ID 和归档 SHA256。教学基线经 PR #10 两项 CI 后合并，再开始个人分支。保留 E7 门禁，在 E8–E10 工作流加入本人独立扩展。

## 替代方案和代价

每次全量 GCC 扫描更简单，但不能演示历史图复用；逐目标失效可减少 helper.o 的多余刷新，但超出本次参考实现的保守策略。完整增量 syscall 图可更贴近论文，却需要更复杂的执行状态更新，本次没有实现。

当前 key 只覆盖平面目录和受限配置，编译器版本字符串不是完整二进制身份，复杂多行预处理不在验证范围。两个对象共同刷新降低潜在收益。性能为 scan 耗时，不能与完整构建时间或论文平均加速比直接比较。只读属性不能约束同为 root 的用户；公共基线仅供克隆，实验写入各自个人目录。

## 实际验证

云端源 SHA 11b733e7d47512fb51562d5ee08c2de1f347048e：13 项单测通过，标准 30 对和新增 5 对完整图/发现一致，三次真实 BuildChecker 对象图核对通过。C1 实际构建重编 main.o 但图复用，C3 复用实际图后两项 MD 消除、RD 保留，证实缓存和发现重算边界。
