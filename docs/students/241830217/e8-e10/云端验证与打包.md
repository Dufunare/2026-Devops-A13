## 4. 个人逐目标缓存扩展的三阶段实测（额外证据）

本脚本独立创建新的受测样例和内部 Git 历史；不会覆盖第 3 步的官方报告。E8 和 E10 **实际执行 BuildChecker 动态复检**（因此必须保留 `SYS_PTRACE`）。

```bash
EXT_E8="work/e8-A-targetwise-241830217-$STAMP"
EXT_E9="work/e9-A-targetwise-241830217-$STAMP"
EXT_E10="work/e10-A-targetwise-241830217-$STAMP"

for stage in e8 e9 e10; do
  case "$stage" in
    e8) target="$EXT_E8"; dyn='--dynamic-recheck' ;;
    e9) target="$EXT_E9"; dyn='' ;;
    e10) target="$EXT_E10"; dyn='--dynamic-recheck' ;;
  esac
  docker run --rm --network none --cap-add SYS_PTRACE \
    --user "$(id -u):$(id -g)" -e HOME=/tmp \
    -v "$PWD:/course" -w /course "course-e8e10:$SID" \
    python3 scripts/e8e10/run_241830217.py \
      --stage "$stage" --out "/course/$target" $dyn \
    > "work/extension-$stage-$STAMP.log" 2>&1
  code=$?
  printf '%s_EXIT=%s OUT=%s\n' "$stage" "$code" "$target"
  if [ "$code" -ne 0 ]; then
    tail -n 80 "work/extension-$stage-$STAMP.log"
    break
  fi
  printf '%s\n' "$SRC_SHA" > "$target/student-source-commit.txt"
  docker image inspect "course-e8e10:$SID" --format '{{.Id}}' > "$target/environment-image-id.txt"
done
```

终端中任一阶段失败，先看错误日志，不填写 `passed`。正常可检查：

```bash

```

E10 `results.csv` 应为 **31 行（1 表头 + 30 数据）**，`performance-summary.csv` 应为 **7 行（1 表头 + 6 场景）**；E8/E10 的 `dynamic_recheck` 应为 `EXECUTED`。计时必须使用真实服务器输出，不能复制聊天或他人结果。
