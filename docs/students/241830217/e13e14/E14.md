## E14 工程修改

### 服务并发与健康

原 `service.py` 使用 `HTTPServer`，DRAFT 在执行长时间 Docker build 时阻塞 `/health`，造成容器 `unhealthy`。改为 `ThreadingHTTPServer`，使健康与长任务可并行处理。用进程内 `threading.Lock` 限制单角色同时仅处理一个 `/v1/run`，第二个请求立即 HTTP 409 + `BUSY`；成功、超时、异常都释放锁。既有角色日志和五阶段响应契约保持兼容。单元测试通过真实 localhost HTTP socket、模拟阻塞处理验证并行健康和 BUSY。

### 镜像源配置

仅 DRAFT 的 Compose `environment` 增加 `EXPERIMENTAL_BUILDKIT_SOURCE_POLICY`，由 `E14_SOURCE_POLICY` 控制；缺省为 E11/E12 已验证的 `/course/labs/e11e12/environment/source-policy.json`，适用于云服务器；CI 指向 `labs/e13e14/source-policy-ci.json`（空 rules，走 Docker Hub 上游），因此无需覆盖通用源码。此文件影响 **Docker registry**，不影响修复候选 Dockerfile 内的 **APT** 软件源；云上仍需使用已保留的清华镜像候选，CI 则使用教师生成的原始候选和 Debian upstream。

### HTTP Timeout

原编排器固定 `urlopen(timeout=720)`，但 DRAFT 有两次各自 `build_timeout=600` 的 Docker build。现为 DRAFT 采用 `max(720, 2*build_timeout+120)` 秒的连接读等待；其余角色仍 720 秒。构建时限本身不变，避免合法的两次慢构建触发更短的外层 HTTP 超时。
