## 源码阅读：`fullcheck.py` 的进程归属与路径过滤

对应 `services/buildchecker/buildchecker/fullcheck.py`：

1. **进程树**（`load_processes`）：每个 `t.PID` 文件对应一个进程。成功的 `clone/fork/vfork` 返回值即子 PID，据此建立父子关系；成功的 `execve` 记录可执行文件名。要求恰好一个 make 进程，缺少子进程 trace、父子关系有歧义或出现 `CLONE_FS` 时直接报 `UNSUPPORTED`，不猜测。
2. **任务归属**（`execution_graph.job_for`）：从某进程沿父链上溯，停在“父进程是 make”的那个进程，以它的 PID 作为任务号；make 本身不属于任何任务。这就是报告中 `job_pid` 字段的来源，也是 cc1 的读取和 as 的写出能合并到同一目标的原因。
3. **工作目录**：`chdir` 更新当前目录，子进程继承 fork 那一刻的目录，而非父进程之后变更的目录。
4. **路径过滤**：
   - 返回值小于 0 的调用（如头文件搜索时的 `ENOENT`）一律跳过；
   - `project_path` 只保留项目根目录内的路径，`/usr/include`、`/tmp/cc*.s` 等系统和临时文件被过滤；
   - 带 `O_DIRECTORY` 或 `O_PATH` 的打开不计入依赖；
   - make 进程自己的只读打开（读 Makefile、检查时间戳）不算编译输入；make 若写项目文件则报 `UNSUPPORTED`；
   - 写打开、`rename` 目标记为输出；任务中被 `unlink` 的中间文件移出输出；任务自己产生的文件和目标本身不算依赖。
5. **目标与依赖**：每个任务恰好一个最终输出，作为目标；该任务成功只读打开的其余项目文件即实际依赖。一个任务多个输出时报 `UNSUPPORTED`。
6. **声明图**（`declaration_graph`）：只解析 `make -p` 数据库 `# Files` 段，跳过 `# Not a target:` 条目和模式规则，展开 `.PHONY` 前置条件，order-only 依赖单独存放。
7. **比较**（`analyze`）：逐目标做集合差，MD 附读取与输出两条系统调用证据，RD 附 Make 数据库行号，并说明 RD 只针对本次构建配置。
