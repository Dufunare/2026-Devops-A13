# E5–E7 实验任务

目标：复现论文的核心流程，将流程整理为可执行程序，再用测试和 CI 验证结果。

## 1. 分组任务

|阶段|A 组：BuildChecker|B 组：DRAFT|提交内容|
|---|---|---|---|
|E5：复现|跟踪构建，比较实际读取与 Makefile 声明|构建失败样例，根据错误日志取得修复候选|复现说明、原始日志|
|E6：MVP|生成实际图、声明图和 MD/RD 报告；修复后复检|执行初始构建、候选构建和程序验证|代码、报告、构建与运行日志|
|E7：验证|重复检测，测试修复、失败和超时场景|测试正常、错误输出、无效候选、构建失败和超时|测试结果、CI、合并拦截记录|

## 2. 目录

|目录|用途|
|---|---|
|labs/A-buildchecker、labs/B-draft|各组实验仓库，包含参考代码|
|services/|服务实现和单元测试|
|fixtures/|实验项目|
|scripts/|环境检查、实验入口和结果校验|
|work/|每次运行生成的报告和日志|
|ci/|分支保护配置和门禁测试|
|templates/|报告与记录模板|

## 3. 操作约定

- 每人在服务器上使用自己的工作目录，Git 提交身份使用学号。
- 每次重跑使用新的 `--out work/目录名`，保留前一次结果。
- 完成已有样例后，补充至少一项测试，修改代码后重新构建镜像。
- 报告列明使用的参考代码、自己的修改、运行命令和结果路径。

A 的检测样例使用单个 Make 进程，每个构建任务生成一个最终输出。RD 表示该依赖在当前构建配置下未被读取。

B 先通过对话模型取得 Dockerfile，再执行构建与验证。`--candidate` 使用自己保存的候选；`--replay` 使用包内的 DeepSeek 候选。候选来源填写在 templates/候选来源记录.json。
